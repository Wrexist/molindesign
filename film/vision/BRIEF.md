## 1. Topic and one hard idea

**Claude takes in a photo as 28-pixel squares, each one a token counted like the words you type, and every photo has a cap on squares. So a 12-megapixel photo is shrunk to under a third of its pixels before the model looks at it (about 4,740 squares on Claude 4.7 and later), which can make small text hard to read; for fine print, get closer.**

Story order: the stake (your photo is shrunk first) → the number (12 million pixels → under a third) → the question (why throw them away?) → mechanism: squares, not pixels → each square is a token → counted like your words → every photo has a token cap → **hero: your photo is about 4,700 squares** (stamp + hold) → consequence: small text might get hard to read → the tip: get closer → question that loops into line 1.

**Native move: the grid knife.** A paper ruler with 28-px teeth that slices the print into squares. It *is* the mechanism (patches), it reads with the sound off, and it can come back at the end as the thing the viewer now knows is coming.

**Main search phrase: `how AI sees images`** (the topic as an American would type it; not spoken verbatim, so show **HOW AI SEES YOUR PHOTO** in the caption's first line and the title). Spoken in the first 2 s: "photo" + "Claude". Secondary (volumes not checked): `claude image upload`, `ai image tokens`, `why ai can't read small text`, `vision transformer`, `image patches`.

**DM-able moment:** "Send Claude 12 million pixels, it keeps under a third." Second (pinned comment): the 2020 Google paper that made this idea famous is titled **"An Image is Worth 16x16 Words."** Third: the tip itself ("get closer for fine print").

**Proposed YouTube title:** **"Why AI Shrinks Your Photos 🤔"** is too broad (false for OpenAI's newest models, fact 6). Use **"Why Claude Shrinks Your Photos 🤔"**. Alternatives: "What Claude Does To Your Photo 😮", "Your Photo Is 4,740 Squares To AI 🤔" (needs "Claude" in the caption's first line).

**Derived (our math with the docs' own code, fact 5; list on screen as OUR MATH)**
- 12 MP photo = **4032 × 3024 = 12,192,768 pixels** (a common 4:3 12-megapixel size; we don't claim it is any one phone's default).
- Unshrunk it would need ⌈4032/28⌉ × ⌈3024/28⌉ = 144 × 108 = **15,552** squares, over both caps.
- High-resolution tier (Claude 4.7 and later): → **2212 × 1659** = 3,669,708 px = **30.1 %** of the pixels; ⌈2212/28⌉ × ⌈1659/28⌉ = 79 × 60 = **4,740** visual tokens (cap 4,784). Voice: "about forty-seven hundred".
- Standard tier (all other models): → **1270 × 952** = 1,209,040 px = **9.9 %**; 46 × 34 = **1,564** tokens (cap 1,568).
- "Under a third" is true on both tiers (30.1 % and 9.9 %). The hero number 4,740 is high-resolution tier only, so it carries **CLAUDE 4.7 AND LATER** and the voice says "on newer models".
- Code check: the same code gives 1920×1080 → 1456×819 / 1,560 tokens (standard) and 1075×1520 → 924×1307, exactly as the docs print.

**Wording choices tied to sources**
- `hook` "Your photo? Claude shrinks it first.": fact 2 ("downscaled before processing") for any photo over the limits; a 12 MP photo is over them on every Claude model (derived).
- `send` "Send it 12 million pixels." sets up the example; the screen shows 4032 × 3024.
- `third` "It cuts that to under a third.": derived (30.1 % / 9.9 %). "That" = the pixel count.
- `ask` makes no claim.
- `squares` "Because it works in squares, not pixels.": fact 1 ("processes images in patches instead of pixels"). "Because" is a fair link: the cap is in squares (fact 2, "visual-token limit").
- `token` "Each 28-pixel square is one token.": fact 1 ("a 28×28-pixel block… referred to as a visual token").
- `counted` "Counted like the words you type.": fact 3 (images priced by the model's per-token input price, the same price text input pays). Not "they *are* words".
- `cap` "And every photo has a token cap.": fact 2 (per-model visual-token limit, applied per image).
- `hero` "On newer models, your photo is about 4,700 squares.": derived, high-resolution tier; "newer models" = "Claude 4.7 and later models" (fact 2).
- `blur` "So small text might get hard to read.": fact 4, hedge kept ("might… make text less legible").

- `end` asks the viewer; no claim.

**Kept out on purpose (overclaims and second ideas)**
- "AI sees your photo like you do" / "it sees" / "understands": the docs say "processes". The voice never says "sees".
- "AI shrinks your photo" (general): false for OpenAI's newest models at default detail (fact 6). Scoped to Claude.
- "Claude is a Vision Transformer" / "Claude uses 16×16 squares": Anthropic doesn't publish Claude's architecture; its docs only define 28-px patches as the unit of tokens and cost. ViT is background (pinned comment), never shown as Claude's design.
- "Squares are words" / "the same tokens as text": the docs say "visual token"; the shared thing is how they're counted and priced. The voice says "counted like".
- "Throws away 70 %" as a hard figure in the voice: only true on one tier; "under a third" is true on both.
- Whether claude.ai (the app) applies exactly these limits: the docs describe the models and the API. The voice says "Claude" and "newer models", which the docs support; the app isn't named. See §5.4.
- Prices ($ per thousand images): true but a second idea (and model-specific).
- People identification, counting, rotation limits: true, a second idea each.
